# Recovery Limitations (honest, mandatory)

This project is **maximum-fidelity archival + reconstruction**, not a Telegram
database rollback. The canonical archive preserves everything readable; the
import restores what Telegram's protocol supports. Nothing unsupported is ever
faked as restored.

## What Telegram's import protocol DOES restore (verified against target MTProto)

- Text (`FULL`)
- Historical date in `fwd_from.date` metadata (`IMPORTED_METADATA_ONLY`)
- Media objects: photo, video, animation/GIF, document, voice, audio as real
  `MessageMedia*` (`PHOTO_EXACT`, `VIDEO_EXACT`, …)
- Re-mapped sender attribution (`SENDER_MAPPED_TO_IMPORTER`, expected)

## What it does NOT restore (archive-only unless reconstructed)

- **`message.date` equal to the original historical instant** — Telegram keeps
  imported messages' visible `message.date` at (near) import time; the original
  instant survives only in `fwd_from.date`. This is `IMPORTED_METADATA_ONLY`,
  *never* `TIMESTAMP_RESTORED`. (Experiment: TIMELINE_MATERIALIZATION_EXPERIMENT.md)
- Sender identity (authors are re-mapped to the importing account)
- Reactions (type/count/voters/timestamp) — history import carries none
- Reply relationships, forward provenance, message entities (incl. custom emoji
  **document_id** preserved in archive only)
- Sticker *entity* (set/emoji) — sticker lands as a document
- Custom emoji semantics in the target
- Album grouping, polls, contacts, geo, service messages
- Original source message ID (target gets a NEW ID)

## Classification vocabulary

Every field/source-message is labeled EXACTLY one of:

1. `EXACTLY RESTORED` — target object matches source semantics (e.g. text, media object types)
2. `PARTIALLY RESTORED` — the field survived but degraded (e.g. sticker→document)
3. `CURRENT STATE RECONSTRUCTED` — re-applied via a non-import method *today* (e.g. sendReaction); not historical
4. `ARCHIVED ONLY` — preserved in the archive, not in the target
5. `FAILED` — neither restored nor reconstructed

`fwd_from.date` is NEVER called a restored message date; `target_has_media_object`
is NEVER called media restored unless the actual constructor matches the source;
archived reactions are NEVER called restored reactions; text-matched is NEVER
called message-restored.

## Distinct identifiers

- original source Message ID (from the archive)
- imported target Message ID (generated by Telegram during import)

These are different concepts and never equated.
