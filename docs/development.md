# Development

## Prerequisites

- Python 3.12+
- Node.js 20+
- Docker + Compose v2 (for the full stack / integration tests)
- Telegram API credentials from https://my.telegram.org (only needed for live tests)

## Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### Run

```bash
# SQLite (zero-config local dev):
uvicorn app.main:app --reload --port 8000

# PostgreSQL (recommended, closer to prod):
docker compose up -d postgres redis
export DATABASE_URL="postgresql+asyncpg://archiver:change-me-strong-password@localhost:5432/telegram_archiver"
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

### Tests

```bash
pytest                      # hermetic (in-memory SQLite)
# or against real Postgres:
TEST_DATABASE_URL="postgresql+asyncpg://archiver:archiver@localhost:5432/telegram_archiver" pytest
```

Live Telegram tests (Phase 7) are gated behind `LIVE_TELEGRAM_*` env vars and a
`live` marker:

```bash
pytest -m live
```

### Migrations

```bash
alembic revision --autogenerate -m "describe change"   # after model edits
alembic upgrade head
alembic downgrade -1                                    # rollback
```

Always review autogenerated migrations before committing.

### Linting

```bash
ruff check app tests
ruff format --check app tests
```

## Frontend

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173, proxies /api to :8000
npm run build      # type-check + production build
```

## Full stack

```bash
cp .env.example .env   # edit secrets
docker compose up -d --build
```

- Backend API: http://localhost/api/docs
- Dashboard: http://localhost

## CI

`.github/workflows/ci.yml` runs on push/PR:

- backend: `ruff check` + `pytest` against a GitHub-hosted Postgres 16 service
  (`TEST_DATABASE_URL` set)
- frontend: `npm ci && npm run build`

## Contributing workflow

1. Branch from `main` (`git switch -c feat/...`).
2. TDD: failing test → implementation → green test.
3. `ruff` clean, full `pytest` green.
4. Update `CHANGELOG.md` and `docs/` as appropriate.
5. Commit with a conventional message; push; open a PR.

## Phase checklist (per plan phase)

Every phase ends with: run tests → update `README.md` → update `CHANGELOG.md` →
commit → push. See `PROJECT_PLAN.md` §15 for the phase breakdown.
